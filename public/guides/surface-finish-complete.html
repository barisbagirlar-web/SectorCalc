Ra (arithmetical mean) and Rz (average peak-to-valley) describe different statistics of the same profile. Treating them as interchangeable without an explicit conversion assumption causes scrap, supplier fights, and first-article loops. SectorCalc SC-028 converts common roughness parameters with the conversion basis visible on the page — free, no sign-in. Converters align language; measured capability still owns production release.

Ra vs Rz — different statistics

Ra averages absolute deviations from the mean line. Rz emphasises peak-to-valley height over sampling lengths. A process can “pass Ra” and “fail Rz” on the same surface because the metrics weight the profile differently. That is not a calculator bug — it is physics of the definition.

Read acceptance language first

Before converting anything, confirm which parameter the drawing and customer standard actually use. If the print says Ra 1.6 and the customer measures Rz, you do not “fix” the print by silently converting — you negotiate the acceptance language or measure what is specified.

Convert with visible assumptions

Parameter translation only with a documented conversion basis

Put the assumption on the traveler. SectorCalc shows the basis on the calculator page so two engineers can reproduce the same screening number. Do not convert “by feel” from a laminated shop chart of unknown origin.

Metrology capability owns release

Instrument tip radius, filter settings, and evaluation length change reported values. If the customer requires Rz, measure Rz with a capable method. A converter does not upgrade an instrument that cannot see the accepted parameter.

Worked pattern: drawing Ra, shop Rz

  1. Quote the governing surface-texture standard from the print.
  2. Identify the acceptance parameter (Ra, Rz, or other).
  3. Run open SC-028 and enter the known value.
  4. Copy the conversion assumption into the traveler.
  5. Confirm the shop can measure the accepted parameter before FAI.

Pair with fits on seats

Bearing seats and sealing surfaces often carry both a fit and a finish. Use free SC-027 alongside SC-028 when both callouts gate release. If assembly closure is the real risk, escalate to SC-008.

Common failure modes

  • Releasing an Ra callout as an Rz limit.
  • Converting without documenting the basis.
  • Ignoring instrument capability.
  • Using converter output alone as PPAP proof.

Filters, cutoff, and why numbers disagree

Two shops can measure the “same” surface and disagree by tens of percent if filter type, cutoff wavelength, and evaluation length differ. Before you argue about Ra vs Rz conversion, lock the metrology recipe named on the print or in the customer standard. A converter cannot repair mismatched filter settings.

When SectorCalc shows a conversion assumption, treat it as language alignment for travelers and RFQs — then confirm the acceptance metrology can actually execute the accepted parameter with the required filter stack.

Drawing notes that prevent scrap

  • Name the parameter (Ra, Rz, …) explicitly — never “finish 32” without a system.
  • Name the standard edition when the customer requires it.
  • Call out special evaluation length or Motif parameters when used.
  • Separate cosmetic finish from functional sealing/bearing seats.

Process capability still owns release

Even a perfect conversion does not prove the process can hold the callout. Use capability studies on the accepted parameter. Predicted conversions are not Cpk. If the shop historically reports Rz while the print demands Ra, schedule method alignment before PPAP — not during the customer witness.

How supplier fights usually start

  1. Design inherits Ra from a material note template.
  2. Inspection reports Rz because the portable instrument defaults there.
  3. Someone multiplies by a tribal factor from a whiteboard.
  4. FAI fails; everyone debates the factor instead of the acceptance language.

Break the loop: write the acceptance parameter, measure it, and only convert with a documented basis when temporary screening is required.

Additional FAQ

What if the print uses both Ra and Rz?

Treat them as independent acceptance criteria unless the customer explicitly allows conversion between them. Measure both if required.

Can I average Ra across a lot and convert once?

No. Conversion is not a substitute for lot metrology on the accepted parameter.

Does polishing always lower Rz more than Ra?

Not reliably. Process changes redistribute the profile; verify with measurement.
