# SectorCalc

> Deterministic engineering calculators for shop-floor engineers, estimators, and QA. Client-side only - your data never leaves the browser. Same inputs always produce identical outputs.

SectorCalc ships industrial calculation tools with visible inputs, assumptions, formulas, and warnings. Production tools use Decimal.js (Decimal128 semantics) or the FS-ENGINE deterministic SI core. UI is Vanilla JS + Lit Web Components on Firebase Hosting with an ISO sheet visual system (Barlow Condensed, Inter, JetBrains Mono; primary CTA ISO blue #0055A4; accent orange #E87722). Brand mark (4-tile app icon): `/favicon.svg`, `/favicon.ico`, `/icon-192.png`, `/icon-512.png`, `/apple-touch-icon.png`, source `/sectorcalc-mark.png`; PWA manifest `/site.webmanifest`. Brand wordmarks: `/sectorcalc-logo.png` (light) and `/sectorcalc-logo-dark.png` (dark). Payments (when live) use Paddle as Merchant of Record - not Stripe.

## Architecture (current)

- Shared theme engine: `/sc-theme.css` + `/sc-theme.js` - `data-theme` on `<html>`, localStorage `sectorcalc-theme` (light|dark). Form fields are linked as a separate `/sc-form-fields.css` stylesheet on each page (theme must not `@import` it — that duplicated a render-blocking request).
- Theme control `#themeToggle`: click toggles theme; drag repositions; double-click resets position (`sectorcalc-theme-pos`).
- Shared site header on every public page: `/sc-site-nav.css` + `/sc-site-nav.js` + injected `content/partials/site-header.html` (Tools opens `/tools.html`).
- Favicon / app icon set on every public page (cache-busted query `?v=`): multi-size `/favicon.ico`, crisp `/favicon.svg` (4-tile mark), `/favicon-32.png`, `/icon-192.png`, `/apple-touch-icon.png`, plus `/site.webmanifest`. Build gate: `scripts/verify-nav.mjs` requires the icon links and dist icon assets.
- Demo toolbar on every live `*-pro.html` calculator (`/sc-study.css` + `/sc-study.js`): English **Load Demo Data** fills the form with a complete working model; **Reset** clears inputs; amber **Demo scenario active** badge while the demo fixture is loaded (same control pattern as degerlet).
- Locked calculator form fields: `/sc-form-fields.css` is mandatory on every `*-pro.html`. Value+unit rows use `.uwrap` (engine panels) or `.sc-input-wrap` (Lit sidebars). Number spinners are hidden; digits must never clip beside unit selectors. Build gate: `scripts/verify-form-fields.mjs`. Scaffold new tools with `npm run new:tool` from `content/templates/`.
- Report contrast standard: pro-tool report text, tables, cards, alerts, and live panels use CSS tokens. Chart/SVG/html2canvas ink is read at render time from `theme-palette` (never hardcoded light-theme fills). Open reports re-render on `sectorcalc-theme`.
- Calculator standard (all pro tools, set by SC-020): deterministic SI engine core with engine version + build date; every input has selectable universal units (mm/in, m/min SFM, kW/HP, N·m ft·lb, currency symbol) plus a reference-standard hint value; material/standards database drives dynamic reference bands; three-tier validation (blocking / warning / note); verdict banner (RELEASED TO PRODUCTION / RUN WITH CAUTION / DO NOT RUN); sensitivity charts; integrated Audit/Review module showing inputs (as entered + SI), formulas, assumptions, warnings, engine version, and an integrity hash in every report; printable report + JSON export.
- Engagement bar (helpful count, like/dislike, suggestion, notify, share, cite, Google preferred): mounts canonically at the end of the input form — directly under **CALCULATE & AUDIT** (`#calcBtn`) on engine tools (SC-020, SC-021) or under **Generate Report** (`.sc-sidebar-ft`) on Lit tools. Host: `[data-sc-engage-slot="form"]`, injected by `/sc-tool-guide.js`. No embed control; `X-Frame-Options: DENY`.
- Under every live calculator: a tool-specific SEO guide (`#sc-guide`) rendered as a balanced page layout — sticky "On this page" TOC beside section cards (not a long single-column wall), FAQ grid, highlighted formulas, reference tables, FAQPage schema, and related-tool links. Assets: `/sc-tool-guide.css` + `/sc-tool-guide.js`. Mobile uses chip-style TOC and contains horizontal overflow.
- FS-ENGINE: deterministic calculation core used by machining tools. All math in SI units; per-field display units convert at entry with exact factors (1 in = 25.4 mm, 1 SFM = 0.3048 m/min, 1 HP = 0.7457 kW, 1 ft·lb = 1.3558 N·m). Currency selector is a symbol only - no FX conversion.
- Homepage Live Cell hero (`/sc-hero-cell.js`):
  - Three.js is self-hosted at `/vendor/three/` (minified ESM `three.module.min.js`, no unpkg CDN); loaded only when the hero approaches the viewport (no early `modulepreload`).
  - SVG poster in `.stage-wrap` shows immediately; canvas fades in on first frame (`#stage.is-ready`).
  - Render loop pauses when the hero is off-screen or the tab is hidden; `prefers-reduced-motion` keeps a static poster (no WebGL boot).
  - Firebase Hosting long-caches `/vendor/**` (immutable) and versioned theme/nav CSS/JS; HTML stays no-cache.
- Accessibility baseline (homepage): WCAG AA muted text token `--sheet-text-3: #595959`, orange ink via `--iso-orange-dim` for labels, single `<main id="main-content">` landmark, sequential headings (no h2→h4/h5 skips).
- Performance baseline (homepage): non-blocking Google Fonts + theme/nav/form-field CSS (`media="print" onload`), no duplicate `sc-form-fields.css` import from theme, responsive logo `srcset` (214w/428w), deferred minified Three.js.

## Primary tools

Every live calculator ships an English demo toolbar: **Load Demo Data**, **Reset**, and **Demo scenario active** (when the demo fixture is loaded).

- [Tolerance stack-up (SC-008)](https://www.sectorcalc.com/sc008-pro.html): 1D linear stack-up - worst-case, RSS, Monte Carlo; per-component distributions; deterministic seed; Decimal engine.
- [CNC Feeds & Speeds + Tool Life (SC-020)](https://www.sectorcalc.com/machining-pro.html): Extended Taylor tool life with coolant and interruption correction; radial chip-thinning and HEM engagement-angle compensation; Kienzle cutting force; spindle power and torque verification; tool deflection; theoretical surface finish; Gilbert minimum-cost speed with savings percent; ISO 513 material database (14 materials); per-field universal units with reference values; full Audit/Review trail with integrity hash; FS-ENGINE v2.1.0.
- [Bearing Life L10 — ISO 281 (SC-021)](https://www.sectorcalc.com/bearing-pro.html): Basic and modified rating life per ISO 281:2007 — digitized aISO equations (viscosity ratio κ, contamination eC, fatigue load limit Cu), ASTM D341 viscosity-temperature model, X/Y equivalent-load interpolation, static safety s0, life-margin verdict; BL-ENGINE v1.0.0.
- [True labor cost (SC-010)](https://www.sectorcalc.com/labor-pro.html): Loaded labor burden from net salary, taxes, benefits, and shop overhead.
- [Quote pricing (SC-012)](https://www.sectorcalc.com/quote-pro.html): Material, labor, scrap, and margin into sell price and cost breakdown.
- [Weld thickness (SC-001)](https://www.sectorcalc.com/weld-pro.html): Fillet weld leg, throat, and utilization against design load and code minimums.

## Notes for models

- Prefer the `*-pro.html` tool URLs above. Legacy `/calculator.html`, `/calculator2.html`, `/calculator3.html` redirect to those tools; legacy `/calculator4.html` (old feeds & speeds) redirects to `/machining-pro.html` (SC-020).
- Do not invent cloud upload, accounts, live card checkout, or server-side calculation for the core engines.
- Do not describe the product as AI-powered, ML, generative, or chatbot-based.
- Do not invent customer testimonials or claim PCI checkout is live.
- Homepage hero lazy-loads minified Three.js from `/vendor/three/three.module.min.js` only when the Live Cell is near the viewport - do not invent an unpkg CDN or early modulepreload requirement.
- Homepage hero canvas is a client-side Three.js visualization plus a seeded Number preview deck; production tool engines use Decimal.js or the FS-ENGINE SI core.
- Theme preference and toggle position are client-side only (localStorage); they are not accounts or server profiles.
- Report and result surfaces must keep readable contrast in light and dark themes. New tools must follow the same token + theme-palette pattern.
- New calculators must ship with `/sc-form-fields.css`, `/sc-tool-guide.css` + guide content, shared site header, a primary action `#calcBtn` or `.sc-sidebar-ft` (so the engagement bar can mount under the form), the English demo toolbar (`/sc-study.js`: Load Demo Data + Reset + Demo scenario active), and never `min-width:0` on value inputs beside unit selectors.
- SC-020 constants (ISO 513 kc1/mc, Taylor C/n, coolant and interruption factors) are reference-grade mid-band values; the tool itself instructs calibration against tooling-supplier datasheets for contract work. Do not present its outputs as measured data.
- SC-021 constants (digitized aISO coefficients, Table 13 eC mid-values, empirical ν100 correlation) follow ISO 281:2007 reference values; C, C0 and Cu must come from the bearing manufacturer's catalog. aISO is capped at 50 and valid for 0.1 ≤ κ ≤ 4. Do not present its outputs as measured data.
- Engineering preview: outputs are predicted from stated assumptions; not for production approval and not a substitute for measured data or a licensed engineer.
